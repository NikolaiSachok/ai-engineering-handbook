# Как устроен курс и как с ним работать

Цель — научиться проектировать, собирать, защищать и эксплуатировать LLM-сервис на .NET в Azure и обосновывать каждое решение на архитектурном ревью. Учебный сервис будем проектировать с учётом требований промышленной эксплуатации.

Этот курс рассчитан на опытного инженера, который мало работал с облаками или лишь немного знаком с другой облачной платформой. Возможно, твой последний проект на .NET был ещё во времена .NET Framework. Возможно, ты впервые берёшься за .NET. Понадобится опыт разработки и промышленной эксплуатации систем; знание Azure и современного .NET заранее не требуется.

Каждое понятие Azure разбираем начиная с задачи: какую проблему нужно решить и какой механизм для этого предлагает платформа. Для понимания объяснений не нужно заранее знать AWS или Google Cloud. За подробностями будем обращаться к Microsoft Learn. В уроках сосредоточимся на выборе решений, компромиссах и возможных сбоях.

Во всех частях курса будем работать с AI-нагрузками. Поэтому в теме удостоверений выясним, как дать сервису доступ к модели и данным. А в теме развёртывания — как проверять изменения, наблюдать за работой сервиса после их выпуска и при необходимости откатывать их.

За AI-основами, на которые опирается курс, обращайся к [RAG & Agents](/rag-agents/) и [AI SDLC](/ai-sdlc/). Там объясняются поиск, агенты, оценка и процесс разработки. Здесь будем ссылаться на эти идеи и применять их, не разбирая заново.

:::note[Статус]

Курс пишется поэтапно. Сейчас в работе основы Azure и первые шаги проекта P1 — RAG-сервиса. Страницы с отметкой 🚧 пока не опубликованы.

:::

## Карта курса \{#course-map}

| Часть | Что разберём |
|---|---|
| I — Основы Azure 🚧 | Работу с удостоверениями, сети, вычисления, данные, обмен сообщениями, инфраструктуру, наблюдаемость, а также правила использования платформы и контроль их соблюдения при работе AI-сервиса. |
| II — Современный .NET 🚧 | Платформу, веб-сервисы, конфигурацию, асинхронную работу с потоками данных, доступ к данным, тестирование и подключение AI-сервисов к приложению. |
| III — Запуск LLM в Azure 🚧 | Модели, поиск, агентов, безопасность, оценку и шлюз перед AI-сервисами. |
| IV — Поставка ПО с помощью AI в стеке Microsoft 🚧 | Конвейеры поставки, агенты для написания кода и релизы, которые можно проверить и откатить. |
| V — Проекты 🚧 | Пошаговую сборку сервисов из упражнений к урокам: ты сможешь запустить каждый сервис и объяснить, как он устроен. |

В приложениях к курсу будут три справочных материала, к которым можно возвращаться. Они тоже ещё не написаны:

- Шпаргалка по Azure 🚧 — вся платформа на нескольких страницах для повторения.
- Карта экзаменов 🚧 — какие уроки и шаги проектов соответствуют навыкам, проверяемым на AI-103 и AI-200.
- Глоссарий 🚧 — единые определения терминов курса.

## Как устроен урок \{#how-a-lesson-works}

Урок начинается с проблемы и объяснения того, как решить её средствами Azure или .NET. Затем сравниваем варианты, выясняем, какие сбои возможны и как каждый вариант повлияет на работу AI-сервиса. После этого переходим к практике. В конце урока — «Что перенести в свою практику», «Новые термины» и «Источники».

В каждом блоке «Попробуй» ты выполняешь очередной шаг одного из проектов. В нём есть команды, ожидаемый результат и примечание «Стоимость», а в конце — «Удаление ресурсов». Прочитай о стоимости до создания ресурсов. Прежде чем закончить практическую работу, удали ресурсы.

В курсе три проекта 🚧:

- **P1 — RAG-сервис.** API на .NET отвечает на вопросы по небольшому набору общедоступных документов и указывает источники.
- **P2 — Агент за AI-шлюзом (AI gateway).** Агент вызывает инструменты и запрашивает одобрение действий; доступ контролирует шлюз.
- **P3 — Конвейер загрузки документов (ingestion pipeline).** Это необязательный проект: конвейер обрабатывает поступающие документы и обновляет поисковый индекс.

## Бюджет на упражнения \{#budget}

Начни с кредита бесплатной учётной записи Azure. На 17.10.2026 [предложение Azure](https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account) предусматривает 200 долларов США на 30 дней для новых клиентов, которые соответствуют его условиям. Когда пройдут 30 дней или ты раньше потратишь весь кредит, для продолжения работы нужно будет перейти на оплату по мере использования (pay-as-you-go).

Когда закончится кредит, ориентируйся на учебные расходы в 10 долларов США в месяц. Создай бюджет на эту сумму и настрой оповещения, которые сработают, когда расходы достигнут 50%, 80% и 100% этой суммы. Этот ориентир нужен для планирования упражнений; он не гарантирует размер счёта.

[Бюджет Azure отправляет оповещения](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/tutorial-acm-create-budgets), но не прекращает расходование средств и не влияет на уже работающие ресурсы. Поэтому каждое упражнение заканчивается удалением ресурсов.

## Как использовать курс для подготовки к сертификации \{#certification}

Карта экзаменов связывает материал курса с двумя экзаменами:

- [AI-103 — Developing AI Apps and Agents on Azure](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-103).
- [AI-200 — Developing AI Cloud Solutions on Azure](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-200).

Оба действующих руководства предполагают знание Python, но описывают ожидаемый опыт по-разному: для AI-103 нужен опыт разработки приложений на Python, для AI-200 нужно уверенно программировать на Python.

Проекты этого курса используют .NET. Если готовишься к любому из двух экзаменов, пройди также схемы обучения по Python из строки *Get trained* в соответствующем руководстве. Одни только проекты на .NET не дадут опыта программирования на Python, который предполагают оба руководства.

## Если читаешь курс позже \{#freshness}

Microsoft переименовывает продукты Azure и выводит из эксплуатации версии моделей. Для Microsoft Foundry (раньше Azure AI Foundry) есть [руководство по переходу с классического портала](https://learn.microsoft.com/en-us/azure/foundry/how-to/navigate-from-classic). Для версий моделей действуют [правила жизненного цикла и вывода из эксплуатации](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/model-retirements).

На каждой странице есть дата «Проверено на» и раздел «Источники». У каждого примера кода указано, с какими версиями среды выполнения и пакетов его компилировали. Там же отмечено, запускали ли его в Azure. Если пример расходится с текущим поведением платформы, сначала проверь эти сведения.
