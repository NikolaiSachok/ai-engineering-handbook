# Глоссарий

Здесь собраны определения всех терминов, которые вводятся в уроках. Строка **Новые термины** в конце каждого урока ведёт к его группе. Глоссарий пополняется вместе с курсом.

Проверено на 17.10.2026. Источники каждой группы приведены в разделе «Источники» соответствующего урока.

## Как устроен Azure \{#how-azure-is-organised}

**Тенант (tenant)** — экземпляр Microsoft Entra ID, в котором хранятся удостоверения организации и объекты каталога.

**Группа управления (management group)** — область действия общих правил Azure, объединяющая подписки или другие группы управления. Назначения прав доступа и политик могут распространяться вниз по этой иерархии.

**Подписка (subscription)** — область администрирования ресурсов Azure, в которой накапливаются начисления за потребление сервисов в рамках соответствующих условий оплаты.

**Группа ресурсов (resource group)** — контейнер для ресурсов Azure с общим жизненным циклом, включая их последующее удаление.

**Ресурс (resource)** — объект, которым управляет Azure: например, среда для запуска приложения, учётная запись хранения или база данных.

**Поставщик ресурсов (resource provider)** — служба Azure, которая предоставляет типы ресурсов и обрабатывает операции с их экземплярами.

**Область действия (scope)** — набор ресурсов Azure, на который распространяется назначение настройки управления, например роли или политики.

**Идентификатор ресурса (resource ID)** — полный идентификатор ресурса Azure. Он включает области действия и путь к поставщику, которые определяют место ресурса в иерархии управления.

**Azure Resource Manager (ARM)** — общий слой развёртывания и управления в Azure, который принимает запросы управления и направляет их поставщикам ресурсов.

**Плоскость управления (control plane)** — операции создания, настройки и удаления ресурсов.

**Плоскость данных (data plane)** — операции использования сервиса, который предоставляет ресурс: например, чтение BLOB-объектов или запрос к индексу.

**Регион (region)** — географическая область с центрами обработки данных Azure и обслуживающей инфраструктурой, в которой можно развёртывать региональные сервисы.

**Зона доступности (availability zone)** — отдельная группа центров обработки данных внутри региона Azure. Зона независима от других по электропитанию, охлаждению и сети.

**Зональный ресурс (zonal resource)** — ресурс, развёрнутый в выбранной зоне доступности.

**Ресурс с избыточностью между зонами (zone-redundant resource)** — ресурс, который сервис реплицирует или распределяет по нескольким зонам.

**Тег (tag)** — метаданные в виде пары «имя — значение», назначаемые ресурсу Azure, группе ресурсов или подписке для организации ресурсов и учёта расходов. Ресурсы не наследуют теги группы автоматически.

**Бюджет (budget)** — целевое значение расходов или потребления для заданной области действия и периода. При достижении настроенных порогов отправляются уведомления; потребление не останавливается.

## Удостоверения I — Microsoft Entra ID \{#entra-id}

**Microsoft Entra ID** — сервис Microsoft для управления удостоверениями и доступом людей и рабочих нагрузок.

**Пользователь (user)** — удостоверение в каталоге, которое представляет человека. Пользователь может входить в систему и получать права доступа.

**Группа безопасности (security group)** — группа в каталоге, через членство в которой предоставляют доступ к ресурсам. Это сокращает число индивидуальных назначений прав.

**Регистрация приложения (app registration)** — конфигурация удостоверения приложения в его домашнем тенанте: идентификатор клиента, настройки входа и разрешения API, которые приложение предоставляет клиентам. Объект приложения служит шаблоном для локальных субъектов-служб в тенантах.

**Субъект-служба (service principal)** — локальное удостоверение рабочей нагрузки в тенанте Microsoft Entra. Ему можно выдать права доступа. Для регистраций приложений и управляемых удостоверений используются разные типы субъектов-служб.

**Управляемое удостоверение (managed identity)** — удостоверение рабочей нагрузки, учётными данными которого управляет Azure. Рабочие нагрузки с поддержкой этого механизма могут получать токены доступа Microsoft Entra, не работая с учётными данными напрямую.

**Управляемое удостоверение, назначаемое системой (system-assigned managed identity)** — управляемое удостоверение, жизненный цикл которого связан с одним ресурсом Azure. Удаление ресурса приводит к удалению удостоверения.

**Управляемое удостоверение, назначаемое пользователем (user-assigned managed identity)** — управляемое удостоверение, созданное как отдельный ресурс Azure. Оно существует независимо от рабочих нагрузок, к которым подключено.

**Идентификатор клиента (client ID)** — идентификатор приложения или управляемого удостоверения, по которому его выбирают при настройке аутентификации. Знание идентификатора не доказывает, что вызывающая сторона действует от имени этого удостоверения.

**Идентификатор субъекта (principal ID)** — идентификатор объекта субъекта-службы, который представляет рабочую нагрузку в тенанте. Используется при выдаче прав этому субъекту.

**Идентификатор ресурса Azure (Azure resource ID)** — полный путь Azure Resource Manager, который однозначно указывает на любой ресурс Azure. Например, поле `id` удостоверения, назначаемого пользователем, содержит подписку, группу ресурсов, поставщика, тип и имя ресурса.

**Токен доступа (access token)** — учётные данные, которые предъявляют защищённому API для проверки доступа. Токен выдаётся для конкретной аудитории и действует ограниченное время. Он не связан с текстовыми токенами, которые считает языковая модель.

**Аудитория (audience)** — API, которому предназначен токен. В токене доступа JWT она указана в утверждении `aud`.

**Токен идентификации (ID token)** — токен OpenID Connect, который сообщает клиенту об аутентификации пользователя. Он не предназначен для вызова другого API.

**Аутентификация (authentication)** — установление того, кто обращается к сервису.

**Авторизация (authorisation)** — решение о том, разрешено ли вызывающей стороне выполнить конкретную операцию с ресурсом.

## RBAC и доступ без ключей \{#rbac-and-keyless-access}

**Azure RBAC (управление доступом на основе ролей, role-based access control)** — система авторизации Azure, которая предоставляет субъекту безопасности права на операции в заданной области действия. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/role-based-access-control/overview)

**Определение роли (role definition)** — набор разрешённых операций управления или работы с данными, права на которые можно предоставить субъекту безопасности.

**Назначение роли (role assignment)** — связь между субъектом безопасности, определением роли и областью действия.

**Наследование прав (inheritance)** — распространение назначения роли с родительской области действия на вложенные ресурсы. Более узкое назначение не отменяет унаследованные разрешения.

**DefaultAzureCredential** — класс учётных данных из Azure Identity, который перебирает заранее настроенную цепочку источников токена, включая учётные данные разработчика и рабочей нагрузки в среде выполнения. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/azure/sdk/authentication/credential-chains)

**Детерминированные учётные данные (deterministic credential)** — явно выбранные учётные данные с предсказуемым источником аутентификации. Пример — `ManagedIdentityCredential` для рабочей нагрузки, работающей в Azure.

**Федерация удостоверений рабочей нагрузки (workload identity federation)** — доверие, которое позволяет рабочей нагрузке обменивать токен внешнего поставщика удостоверений на токен доступа Entra без хранения секрета клиента.

**Учётные данные федеративного удостоверения (federated identity credential)** — настройки доверия в Entra, которые задают допустимые значения издателя, субъекта токена и аудитории. Сами по себе они не предоставляют права на ресурсы Azure. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/entra/workload-id/workload-identity-federation-create-trust-user-assigned-managed-identity)

**OIDC (OpenID Connect)** — протокол удостоверения личности, по которому издатель выдаёт токен удостоверения. При федерации между GitHub и Azure этот токен идентифицирует задание и обменивается на токен доступа Entra.

## Сети для разработчика приложений \{#networking}

**Azure Virtual Network (VNet, виртуальная сеть)** — изолированное частное адресное пространство в пределах одного региона и одной подписки, где ресурсы могут взаимодействовать по частной сети. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/concepts-and-best-practices)

**Подсеть (subnet)** — часть адресного пространства VNet, выделенная для ресурсов или интеграции с сервисом. К подсети можно применять средства сетевого контроля.

**Группа безопасности сети (NSG)** — набор правил для входящих и исходящих пакетов с учётом состояния соединений. Правила разрешают или запрещают трафик по адресам, портам и протоколу. Группу привязывают к подсети или сетевому интерфейсу. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/network-security-groups-overview)

**Частная конечная точка (private endpoint)** — сетевой интерфейс с частным IP-адресом в VNet, который обеспечивает подключение к поддерживаемому сервису через Azure Private Link. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/private-link/private-endpoint-overview)

**Конечная точка службы (service endpoint)** — настройка подсети, которая передаёт поддерживаемому сервису Azure удостоверение VNet через магистральную сеть Azure. Адрес назначения при этом остаётся публичным адресом сервиса. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/virtual-network-service-endpoints-overview)

**Частная зона DNS (private DNS zone)** — пространство имён DNS, записи которого доступны через связанные VNet и правильно настроенную пересылку запросов DNS. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/dns/private-dns-virtual-network-links)

**Интеграция с VNet (VNet integration)** — механизм подключения управляемого приложения к VNet. Возможности входящих и исходящих соединений зависят от сервиса размещения. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/app-service/overview-vnet-integration)

**Входящий трафик (ingress)** — трафик, который пересекает рассматриваемую границу приложения или сети по направлению внутрь.

**Исходящий трафик (egress)** — трафик, который пересекает рассматриваемую границу приложения или сети по направлению наружу.

**Топология hub-and-spoke (центральная сеть и периферийные сети)** — топология, в которой VNet рабочих нагрузок подключены к общей центральной VNet ради общих сетевых функций, например DNS, маршрутизации и проверки трафика.

**Пиринг VNet (VNet peering)** — соединение виртуальных сетей для обмена трафиком по частной сети. Пиринг нетранзитивен. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/virtual-networks-faq)

**Брандмауэр веб-приложений (web application firewall, WAF)** — средство проверки запросов HTTP(S) по правилам веб-безопасности для обнаружения или блокировки атак.

## Выбор вычислительной среды \{#compute}

**План App Service (App Service plan)** — вычислительные ресурсы и тарифный уровень, на которых работают одно или несколько приложений App Service.

**Среда Container Apps (Container Apps environment)** — управляемая граница, внутри которой объединены контейнерные приложения и задания с общими настройками сети и журналирования.

**Профиль рабочей нагрузки (workload profile)** — конфигурация Container Apps, которая определяет вычислительные ресурсы и память, доступные назначенным этому профилю приложениям.

**Реплика (replica)** — работающий экземпляр ревизии Container Apps. При масштабировании приложения реплики добавляются или удаляются.

**Ревизия (revision)** — неизменяемый снимок образа контейнера приложения и настроек масштабирования.

**Масштабирование до нуля (scale to zero)** — уменьшение числа работающих экземпляров до нуля при отсутствии запросов или задач. Внешний триггер позволяет снова запустить экземпляры, когда появятся новые запросы или задачи.

**Холодный старт (cold start)** — подготовка нового экземпляра приложения к обработке запросов и связанная с ней задержка, включая выделение ресурсов и инициализацию приложения.

**Правило масштабирования (scale rule)** — декларативное соответствие между сигналом спроса на ресурсы, например HTTP-трафиком или числом ожидающих сообщений в очереди, и нужным числом работающих экземпляров.

**Постоянно готовый экземпляр (always-ready instance)** — ресурсы, которые намеренно оставляют запущенными, чтобы сократить задержку при старте. Их оплата зависит от сервиса размещения и плана.

**Пул узлов (node pool)** — группа рабочих узлов Kubernetes с общей конфигурацией, которой кластер управляет как единым целым.

## Хранение данных \{#data}

**Паттерн доступа (access pattern)** — необходимые для рабочей нагрузки операции чтения и записи: по каким ключам находить данные, какие запросы выполнять, как часто обновлять записи и насколько свежими должны быть результаты.

**Объектное хранилище (object storage)** — хранилище именованных объектов: каждый содержит байты и метаданные. Azure Blob Storage использует эту модель для документов и другого неструктурированного содержимого.

**Контейнер блобов (blob container)** — именованная группа блобов в учётной записи хранения Azure. Контейнер также может ограничивать область действия роли, которая предоставляет доступ к данным.

**Основное хранилище (system of record)** — хранилище, где находится основная копия конкретных данных. Производные копии можно восстановить из него или сверить с ним.

**pgvector** — расширение PostgreSQL для хранения векторов и поиска по ним; идентификатор расширения — `vector`.

**Ключ раздела (partition key)** — свойство элемента, по значению которого Azure Cosmos DB определяет логический раздел. От него зависит распределение связанных данных и нагрузки от запросов.

**Единица запроса (request unit, RU)** — нормализованная мера расхода ресурсов на операцию базы данных в Azure Cosmos DB, учитывающая CPU, ввод-вывод и память. Выделенная пропускная способность выражается в `RU/s`.

**Уровень согласованности (consistency level)** — требования к свежести данных и порядку, в котором чтение базы видит результаты записи.

**Cache-aside (кэширование по запросу)** — паттерн, при котором приложение сначала читает кэш. При промахе оно загружает данные из основного хранилища и помещает результат в кэш.

**Срок жизни (TTL)** — срок, по истечении которого сохранённая запись становится просроченной. Он ограничивает время, в течение которого запись можно использовать повторно.

**Инвалидация кэша (cache invalidation)** — удаление или замена кэшированных данных, когда изменение исходных данных делает их непригодными для повторного использования.

**Роль плоскости данных (data-plane role)** — роль Azure, которая предоставляет право выполнять операции [плоскости данных](#how-azure-is-organised). Например, `Storage Blob Data Reader` разрешает читать блобы и получать их список.

## Сообщения и события \{#messaging}

**Команда (command)** — сообщение с просьбой выполнить операцию, адресованное потребителю, который отвечает за обработку.

**Событие (event)** — сообщение об изменении, которое уже произошло.

**Поток событий (event stream)** — последовательность наблюдений, к которой потребители обращаются для чтения по мере её накопления; это могут делать несколько независимых приложений.

**Пространство имён Service Bus (namespace)** — контейнер для объектов обмена сообщениями, например очередей и тем, который предоставляет конечную точку для доступа к ним. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/service-bus-messaging/service-bus-messaging-overview)

**Очередь (queue)** — объект брокера, который хранит сообщения для конкурирующих потребителей. Они получают сообщения и сообщают брокеру результат обработки.

**Тема и подписка (topic and subscription)** — механизм публикации и подписки: тема направляет копии сообщений в подписки, из которых потребители читают независимо друг от друга.

**Согласование результата обработки (settlement)** — действие, которым получатель сообщает брокеру исход обработки полученного сообщения: например, подтверждает успех, освобождает сообщение для новой попытки или отправляет его в карантин.

**PeekLock** — режим получения в Service Bus, при котором сообщение временно закреплено за одним получателем. Другой потребитель не может получить его, пока текущий получатель не сообщит брокеру результат обработки или не истечёт блокировка.

**Карантинная очередь (dead-letter queue, DLQ)** — подочередь для сообщений, исключённых из обычной доставки: получатель отклонил их либо их не удалось обработать в пределах правил доставки.

**Сеанс сообщений (message session)** — группа сообщений Service Bus с одним `SessionId`, к которой один получатель имеет исключительный доступ для последовательной обработки связанных сообщений.

**Идемпотентность (idempotency)** — свойство операции: повторное выполнение не вносит новых изменений сверх тех, которые внесло первое успешное выполнение.

**Обнаружение дубликатов (duplicate detection)** — функция брокера, которая в течение настроенного интервала отбрасывает повторные отправки с тем же ключом сообщения.

**Секция (partition)** — упорядоченная часть журнала событий, которую можно обрабатывать независимо от остальных частей.

**Группа потребителей (consumer group)** — независимое представление потока Event Hubs, с помощью которого приложение читает события отдельно от других приложений.

**Контрольная точка (checkpoint)** — сохранённая позиция обработки в секции потока, с которой можно возобновить чтение после прерывания.

## Секреты и конфигурация \{#secrets-and-configuration}

**Секрет Key Vault (Key Vault secret)** — конфиденциальное значение с поддержкой версий, например учётные данные внешнего сервиса. Приложение с соответствующими правами может получить его из Azure Key Vault.

**Криптографический ключ (cryptographic key)** — ключевой материал для операций подписи, шифрования или упаковки другого ключа. В Key Vault это отдельный тип объекта, отличный от секрета.

**Сертификат Key Vault (Key Vault certificate)** — объект сертификата с поддержкой версий и связанными ключом и секретом. Управляется через политики сертификатов и операции их жизненного цикла.

**Модель разрешений RBAC (RBAC permission model)** — модель авторизации Key Vault, в которой доступ к данным предоставляется назначениями ролей Azure вместо прежних политик доступа хранилища.

**Key Vault Secrets User** — встроенная роль Azure, которая разрешает читать содержимое секретов Key Vault, включая секретную часть сертификата, но не даёт прав на запись секретов.

**Azure App Configuration** — сервис Azure для централизованного управления настройками приложения и флагами функций.

**Метка App Configuration (label)** — необязательный атрибут, который различает варианты одного ключа: например, значения для разных сред.

**Ссылка на Key Vault** — URI секрета, сохранённый вместо самих учётных данных. Поставщик App Configuration или Container Apps получает по нему значение, отдельно проходя аутентификацию в Key Vault.

**Ротация (rotation)** — замена учётных данных или криптографического объекта с согласованным переходом приложений на новую версию, после которого прежнюю версию можно безопасно отключить.

**Обратимое удаление (soft delete)** — сохранение удалённого хранилища или объекта в состоянии, доступном для восстановления, в течение заданного срока.

**Защита от окончательного удаления (purge protection)** — механизм Key Vault, который запрещает окончательно удалять обратимо удалённое хранилище или объект до конца срока хранения.

## Инфраструктура как код \{#infrastructure-as-code}

**Инфраструктура как код (infrastructure as code, IaC)** — описание желаемой конфигурации инфраструктуры в файлах, которые можно версионировать, проверять и передавать инструментам развёртывания.

**Шаблон ARM (ARM template)** — декларативное описание развёртывания в формате JSON, которое передают Azure Resource Manager — слою развёртывания и управления в Azure.

**Bicep** — декларативный язык описания инфраструктуры Azure, который компилируется в шаблоны ARM JSON.

**Состояние Terraform (Terraform state)** — сохранённые соответствия и метаданные, с помощью которых Terraform связывает конфигурацию с управляемой инфраструктурой.

**Модуль (module)** — в Bicep описание развёртывания, которое вызывают из другого файла. Объединяет связанные ресурсы и предоставляет параметры и выходные значения для работы с ними.

**What-if** — операция ARM, которая прогнозирует изменения ресурсов и их свойств при предлагаемом развёртывании, не применяя эти изменения.

**Расхождение конфигурации (configuration drift)** — отличие фактической конфигурации окружения от желаемой конфигурации в исходных файлах.

**Инкрементное развёртывание (incremental deployment)** — режим ARM по умолчанию: ресурсы, не включённые в шаблон, сохраняются, а свойства объявленных ресурсов применяются заново. Пропущенные свойства объявленных ресурсов сбрасываются к значениям по умолчанию. [Режимы развёртывания](https://learn.microsoft.com/ru-ru/azure/azure-resource-manager/templates/deployment-modes).

**Azure Developer CLI (`azd`)** — инструмент, который на основе конфигурации проекта и инфраструктуры как кода координирует упаковку приложения, подготовку инфраструктуры и развёртывание приложения.

## Наблюдаемость \{#observability}

**Наблюдаемость (observability)** — возможность исследовать поведение работающей системы по телеметрии, которую она формирует.

**Azure Monitor** — платформа Azure для сбора и анализа телеметрии приложений и инфраструктуры, а также реагирования на основе этих данных.

**Рабочая область Log Analytics (Log Analytics workspace)** — ресурс Azure для хранения таблиц журналов и трейсов. В пределах рабочей области настраивают таблицы и права на выполнение запросов к ним.

**Log Analytics** — инструмент портала Azure для написания и выполнения запросов к данным журналов.

**Application Insights** — средство мониторинга производительности приложений в составе Azure Monitor. Ресурсы на основе рабочей области хранят телеметрию в связанной рабочей области Log Analytics.

**Дистрибутив OpenTelemetry (OpenTelemetry distribution)** — комплект из SDK OpenTelemetry, библиотек инструментирования и настроек для сбора и экспорта телеметрии.

**Телеметрия запросов (request telemetry)** — записи о входящих операциях приложения, в том числе об их длительности и успешности.

**Телеметрия зависимостей (dependency telemetry)** — записи об исходящих вызовах из приложения к другим сервисам или системам.

**KQL (Kusto Query Language)** — язык запросов для фильтрации, объединения и агрегации таблиц в Azure Monitor Logs.

**Приём данных (ingestion)** — поступление телеметрии в хранилище данных мониторинга. Объём собранных данных — один из основных факторов стоимости.

**Срок хранения (retention)** — период, в течение которого данные таблицы остаются доступными. Его задают отдельно для таблицы или наследуют из настроек рабочей области по умолчанию. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/azure-monitor/logs/data-retention-configure)

**Сэмплирование (sampling)** — сохранение телеметрии лишь для части операций. Это уменьшает объём данных, но отдельные записи теряются.

**Дневной лимит приёма данных (daily cap)** — порог объёма данных для рабочей области. При его достижении сбор для затронутых таблиц останавливается до сброса лимита. Возможны пропуски в телеметрии и оплачиваемое превышение порога.

## Правила использования платформы и архитектурные рекомендации \{#governance-and-frameworks}

**Azure Policy** — сервис Azure, который проверяет ресурсы по правилам конфигурации и применяет заданные в них эффекты.

**Определение политики (policy definition)** — повторно используемое правило, содержащее условия, эффект и параметры, необходимые для проверки ресурса.

**Эффект политики (policy effect)** — действие при выполнении условия политики: например, аудит, отклонение запроса, изменение поддерживаемых свойств или развёртывание связанного ресурса.

**Назначение политики (policy assignment)** — связь определения политики или инициативы с областью действия, включающая значения параметров и настройки применения эффектов.

**Инициатива политик (policy initiative)** — группа определений для общей цели, которыми управляют и которые назначают вместе. Другое название — набор политик (policy set).

**Состояние соответствия (compliance state)** — результат проверки ресурса по назначенной политике, которая к нему применима.

**Cloud Adoption Framework (CAF)** — рекомендации Microsoft по планированию, подготовке, освоению и эксплуатации облачных сред, включая общие правила их использования, контроль соблюдения этих правил и распределение ответственности в организации.

**Целевая зона (landing zone)** — среда Azure с общими правилами, в которой предусмотрены организация ресурсов, доступ, сети и порядок эксплуатации, необходимые для размещения рабочих нагрузок.

**Well-Architected Framework** — рекомендации по проектированию и архитектурному ревью рабочих нагрузок Azure. Охватывают пять направлений: надёжность (Reliability), безопасность (Security), оптимизация затрат (Cost Optimization), операционная эффективность (Operational Excellence) и эффективность производительности (Performance Efficiency).

**Cost Management** — возможности Microsoft для анализа, мониторинга и оптимизации облачных расходов.

**Microsoft Defender for Cloud** — сервис Microsoft для проверки состояния безопасности и защиты рабочих нагрузок. Набор доступных возможностей зависит от включённых планов.

**Управление состоянием безопасности облака (cloud security posture management, CSPM)** — проверка конфигурации облачных ресурсов, которая выявляет недостатки безопасности и помогает выбрать меры по их устранению.

## Платформа .NET сегодня \{#dotnet-platform}

**Среда выполнения (runtime)** — компонент, который исполняет код приложения и предоставляет необходимые для этого механизмы, включая сборку мусора.

**SDK (software development kit)** — инструменты, среда выполнения и библиотеки для создания, сборки и запуска приложений .NET при разработке.

**Проект в стиле SDK (SDK-style project)** — файл проекта MSBuild, который выбирает SDK проекта и наследует его правила сборки и соглашения о включении файлов по умолчанию.

**Идентификатор целевой платформы (target framework moniker, TFM)** — обозначение в файле проекта, которое задаёт доступный проекту набор API платформы. Пример — `net10.0`.

**`global.json`** — файл конфигурации в рабочем или родительском каталоге, который управляет выбором установленного .NET SDK для инструментов, независимо от целевой платформы проекта.

**Группа компонентов SDK (SDK feature band)** — группа версий .NET SDK с одинаковым разрядом сотен в последнем компоненте номера версии. Она отделяет обновления возможностей инструментов от исправлений внутри группы.

**LTS (Long Term Support)** — категория выпусков .NET с долгосрочной поддержкой на три года. Для сохранения поддержки нужно устанавливать актуальные обновления обслуживания (servicing updates).

**STS (Standard Term Support)** — категория выпусков .NET со стандартной поддержкой на два года по текущей политике. Для этих выпусков тоже нужно устанавливать обновления обслуживания.

**NuGet** — система пакетов .NET для распространения библиотек и инструментов с собственными версиями, разрешения зависимостей и использования этих пакетов.

**`PackageReference`** — элемент MSBuild, который объявляет прямую зависимость проекта от пакета NuGet.

**Транзитивная зависимость (transitive dependency)** — пакет, который требуется приложению косвенно, через другой пакет в графе зависимостей.

**Восстановление зависимостей (restore)** — операция, которая разрешает граф пакетных зависимостей проекта и делает необходимые пакеты доступными для сборки.

**Файл блокировки (lock file)** — файл `packages.lock.json`, в котором записан разрешённый граф зависимостей NuGet. При восстановлении в режиме блокировки этот граф можно проверить.

**Решение (solution)** — файл, который объединяет проекты для инструментов разработки и команд уровня решения. Он не определяет запущенный экземпляр приложения.

## ASP.NET Core \{#aspnet-core}

**Хост (host)** — объект, объединяющий службы приложения, конфигурацию, журналирование, сервер и управление временем жизни приложения.

**Kestrel** — кроссплатформенный HTTP-сервер, который ASP.NET Core использует по умолчанию. [↗](https://learn.microsoft.com/ru-ru/aspnet/core/fundamentals/servers/kestrel?view=aspnetcore-10.0)

**Промежуточное ПО (middleware)** — компонент конвейера обработки HTTP-запросов. Он может обрабатывать запрос и ответ, вызывать следующий компонент или досрочно завершать обработку.

**Досрочное завершение обработки (short-circuiting)** — формирование ответа без вызова оставшейся части конвейера обработки запроса.

**Конечная точка (endpoint)** — исполняемый обработчик запроса со связанными метаданными, который маршрутизация выбирает для обработки HTTP-запроса.

**Минимальное API (minimal API)** — способ создания API в ASP.NET Core, при котором HTTP-маршруты сопоставляются с делегатами обработчиков без обязательных классов контроллеров.

**Контроллер (controller)** — класс, который объединяет действия с использованием соглашений и возможностей ASP.NET Core MVC для конечных точек.

**Группа маршрутов (route group)** — набор конечных точек с общим префиксом маршрута и соглашениями, например метаданными или требованиями авторизации.

**Привязка параметров (parameter binding)** — получение аргументов обработчика конечной точки путём преобразования данных запроса или разрешения зависимостей из зарегистрированных служб.

**Ограничение маршрута (route constraint)** — правило, которое ограничивает сопоставление с маршрутом, чтобы различать конечные точки. Оно не предназначено для проверки входных данных приложения.

**ProblemDetails** — структурированное описание HTTP-ошибки со стандартными полями: тип проблемы, краткое описание проблемы (`title`), код статуса, подробности и идентификатор конкретного случая, а также необязательными расширениями. [↗](https://learn.microsoft.com/ru-ru/aspnet/core/fundamentals/error-handling-api?view=aspnetcore-10.0)

## Основа приложения — Microsoft.Extensions \{#extensions-backbone}

**Внедрение зависимостей (dependency injection, DI)** — передача компоненту нужных ему зависимостей извне вместо их создания внутри самого компонента.

**Время жизни сервиса (service lifetime)** — правило, по которому контейнер DI создаёт и повторно использует экземпляр зарегистрированного сервиса.

**Transient (новый экземпляр при каждом обращении)** — время жизни, при котором контейнер создаёт новый экземпляр каждый раз, когда у него запрашивают сервис.

**Scoped (экземпляр в пределах области DI)** — время жизни, при котором один экземпляр повторно используется внутри одной области DI. В HTTP API ASP.NET Core у каждого запроса своя область DI.

**Singleton (общий экземпляр контейнера)** — время жизни, при котором один экземпляр повторно используется всё время жизни контейнера DI.

**Захваченная зависимость (captive dependency)** — зависимость, которую более долгоживущий потребитель удерживает дольше, чем предусмотрено её временем жизни.

**Поставщик конфигурации (configuration provider)** — компонент, который предоставляет пары «ключ — значение» из источника настроек: например, JSON, переменных среды или аргументов командной строки.

**Паттерн Options (options pattern)** — типизированный доступ к группе связанных настроек конфигурации через класс настроек и сервисы Options.

**Проверка при запуске (startup validation)** — проверка настроенных правил при старте приложения, которая не даёт ему запуститься с недопустимыми настройками.

**Структурированное журналирование (structured logging)** — запись стабильного шаблона сообщения и отдельных именованных значений. Поставщик журналирования может сохранить эти значения как поля, доступные для поиска.

## Асинхронность, потоки данных и отмена \{#async-streaming-cancellation}

**Задача (task)** — объект .NET, который представляет операцию и её будущее завершение: успешное, с ошибкой или отменой. `Task<T>` также предоставляет результат операции.

**Асинхронный поток (async stream)** — последовательность `IAsyncEnumerable<T>`, элементы которой читают через `await foreach`, дожидаясь каждого следующего асинхронно. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/csharp/asynchronous-programming/generate-consume-asynchronous-stream)

**Server-sent events (SSE, события от сервера)** — формат потока событий по HTTP для последовательной передачи сообщений от сервера клиенту по одному соединению.

**Кооперативная отмена (cooperative cancellation)** — остановка работы по общему сигналу отмены. Каждая участвующая операция должна обнаружить этот сигнал и отреагировать на него.

**Токен отмены (cancellation token)** — значение .NET, которое передают операции, чтобы она могла обнаружить сигнал отмены. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/standard/threading/cancellation-in-managed-threads)

**Источник токена отмены (cancellation token source)** — объект .NET, который предоставляет токен и может запросить отмену операций, отслеживающих этот токен.

**Отмена запроса (request cancellation)** — сигнал, доступный в ASP.NET Core через `HttpContext.RequestAborted`, когда клиент или сервер прерывает HTTP-запрос.

**Связанная отмена (linked cancellation)** — объединение сигналов отмены через источник токена. Он переходит в состояние отмены, когда отменён любой из связанных входных токенов.

**Ограничение общего времени выполнения (elapsed-time budget)** — полное время, отведённое на операцию. После его истечения приложение запрашивает отмену, даже если обновления продолжают поступать.

**Тайм-аут простоя (idle timeout)** — ограничение времени, в течение которого операция может не продвигаться: например, ждать следующего обновления потока.

## Доступ к данным \{#data-access}

**Библиотека объектно-реляционного отображения (object-relational mapper, ORM)** — библиотека, которая сопоставляет объекты приложения с таблицами реляционной базы данных и обеспечивает запросы и обновления между ними.

**EF Core (Entity Framework Core)** — библиотека Microsoft для объектно-реляционного отображения в .NET. Поддерживает запросы LINQ, отслеживание изменений сущностей и миграции схемы.

**Поставщик базы данных (database provider)** — реализация для конкретной СУБД, которая подключает к ней EF Core и переводит запросы на её язык.

**DbContext** — объект EF Core для отдельной операции: предоставляет доступ к модели, запросам и отслеживаемым изменениям сущностей.

**Отслеживание изменений (change tracking)** — учёт идентификаторов, состояний сущностей и изменений свойств, по которому EF Core определяет необходимые операции записи при сохранении.

**Запрос без отслеживания (no-tracking query)** — запрос EF Core, после которого контекст не удерживает возвращённые сущности в механизме отслеживания для последующих обновлений.

**Миграция (migration)** — версионируемый набор операций со схемой, который приводит базу данных от одной версии модели приложения к другой.

**Снимок модели (model snapshot)** — сохранённое представление модели EF Core, с которым сравнивается текущая модель при создании следующей миграции.

**Проекция (projection)** — выбор нужной структуры результата, например нескольких столбцов вместо целой сущности.

**Проблема N+1 запросов (N+1 queries)** — один запрос к базе и ещё по одному для каждого из N результатов. Возникает, например, при ленивой загрузке связанных данных или выполнении запросов в цикле по результатам. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/ef/core/performance/efficient-querying)

**Декартовый взрыв (cartesian explosion)** — перемножение строк результата при соединении нескольких коллекций одного уровня: в строках повторяются комбинации элементов этих коллекций.

**Dapper** — микро-ORM для .NET, который преобразует результаты явно написанных SQL-запросов в объекты, без механизма отслеживания изменений EF Core.

**Параметризованный SQL (parameterized SQL)** — SQL, в котором значения данных передаются отдельно от текста команды, поэтому они не интерпретируются как синтаксис SQL.

**Оптимистический контроль параллелизма (optimistic concurrency)** — обнаружение конфликтующих записей путём сравнения ранее прочитанного токена с сохранённым значением при обновлении. При несовпадении приложение должно разрешить конфликт.

**Токен параллелизма (concurrency token)** — свойство, исходное значение которого EF Core сравнивает со значением в базе при сохранении обновления или удаления, чтобы обнаружить конфликтующую запись. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/ef/core/saving/concurrency)

**Разделённый запрос (split query)** — запрос EF Core, который загружает связанные коллекции несколькими SQL-запросами вместо соединения всех коллекций в один результат. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/ef/core/querying/single-split-queries)

**Пакет миграций (migration bundle)** — исполняемый артефакт с миграциями EF Core. Применяет изменения схемы на целевой машине без исходного кода приложения, .NET SDK и инструментов EF. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/ef/core/managing-schemas/migrations/applying#bundles)

## Тестирование \{#testing}

**Модульный тест (unit test)** — исполняемая проверка отдельного поведения приложения в изоляции от остальной системы.

**Интеграционный тест (integration test)** — исполняемая проверка совместной работы нескольких выбранных компонентов приложения.

**xUnit** — фреймворк тестирования для .NET. Тесты объявляются с помощью атрибутов, таких как `Fact` и `Theory`, а их результаты проверяются утверждениями. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/core/testing/unit-testing-csharp-with-xunit)

**Тестовый двойник (test double)** — замена зависимости, которая позволяет управлять её поведением или наблюдать за ним во время теста.

**Упрощённая тестовая реализация (fake)** — тестовый двойник с работающей реализацией, поведение которой намеренно ограничено.

**WebApplicationFactory** — вспомогательный класс ASP.NET Core, который запускает приложение для интеграционных тестов и позволяет менять конфигурацию его тестового хоста. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/aspnet/core/test/integration-tests?view=aspnetcore-10.0)

**TestServer** — сервер ASP.NET Core, работающий внутри процесса и позволяющий проверять HTTP-конвейер приложения в тестах.

**Testcontainers** — библиотека, которая управляет временными контейнерами с зависимостями для тестов.

**Тестовая фикстура (test fixture)** — заранее известная конфигурация среды или данные для тестов с определённым временем жизни и ответственностью за очистку.

## Контейнеры и Aspire \{#containers-and-aspire}

**Образ контейнера (container image)** — упакованная файловая система и конфигурация выполнения, на основе которых создаются экземпляры контейнеров приложения.

**Дайджест образа (image digest)** — идентификатор SHA-256, вычисляемый по содержимому манифеста образа. Позволяет идентифицировать конкретный образ независимо от изменяемого тега. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/container-registry/container-registry-concepts#manifest-digest)

**PublishContainer** — цель .NET SDK, которая создаёт образ контейнера из опубликованного приложения и базового образа без Dockerfile. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/core/containers/sdk-publish)

**AppHost** — проект или файл Aspire, который объявляет ресурсы приложения и связи между ними для оркестрации. ↗ [Aspire](https://aspire.dev/get-started/app-host/)

**Ресурс Aspire (Aspire resource)** — компонент приложения или зависимость, представленные в модели AppHost: например, проект API или контейнер.

**Service Defaults** — общий C#-проект с настройками телеметрии, проверок работоспособности, обнаружения служб и устойчивости HTTP-клиента к сбоям. Эти настройки можно менять. ↗ [Aspire](https://aspire.dev/get-started/csharp-service-defaults/)

**OpenTelemetry** — независимый от поставщика инструментарий для инструментирования приложений, сбора и экспорта телеметрии, включая трейсы, метрики и журналы. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/core/diagnostics/observability-with-otel)

**OTLP (OpenTelemetry Protocol)** — протокол передачи данных OpenTelemetry между приложениями, коллекторами и системами обработки телеметрии. ↗ [Aspire](https://aspire.dev/fundamentals/telemetry/)

**Спан (span)** — запись об одной операции в распределённом трейсе, содержащая время выполнения, контекст и связанные атрибуты.

**Обнаружение служб (service discovery)** — определение доступных клиенту адресов службы по её логическому имени.

**IChatClient** — интерфейс Microsoft.Extensions.AI для обмена сообщениями чата с сервисом модели. Возвращает готовый ответ или поток обновлений. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/ai/ichatclient)

**Адаптер поставщика (provider adapter)** — компонент, который адаптирует клиент из SDK поставщика к общему интерфейсу приложения, преобразуя типы и операции между ними.

**Microsoft.Extensions.VectorData** — абстракции .NET для доступа к векторным хранилищам и коллекциям типизированных записей через реализации поставщиков. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/ai/vector-stores/overview)

**Microsoft Agent Framework** — SDK Microsoft для создания агентов и рабочих процессов с поддержкой инструментов, состояния сеанса и оркестрации. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/agent-framework/overview/)

## Microsoft Foundry \{#microsoft-foundry}

**Ресурс Foundry (Foundry resource)** — ресурс Azure, которому принадлежат общие бессерверные развёртывания моделей и настройки сети и безопасности. Его тип — `Microsoft.CognitiveServices/accounts`, вид — `AIServices`.

**Проект Foundry (Foundry project)** — дочерний ресурс внутри ресурса Foundry. Проект объединяет рабочие материалы, например агентов, оценки, файлы и развёртывания на управляемых вычислительных ресурсах. У проекта свои настройки доступа, которые действуют наряду с общими настройками родительского ресурса.

**Каталог моделей (model catalog)** — перечень доступных моделей с информацией об их возможностях и вариантах развёртывания. Наличие модели в каталоге не создаёт развёртывание и не подтверждает, что подписка позволяет купить предложение.

**Развёртывание модели (model deployment)** — конфигурация с именем, которая задаёт модель и версию для обслуживания запросов. При обращении к развёртыванию в запросе на инференс указывается его имя.

**Конечная точка инференса (inference endpoint)** — адрес API, на который клиент отправляет входные данные модели и откуда получает результат.

**Доступ без ключей (keyless access)** — аутентификация с помощью токенов Microsoft Entra ID вместо сохранённого ключа API сервиса. Для вызова по-прежнему нужны права доступа. Чтобы разрешить только такой способ аутентификации, нужно отключить локальную аутентификацию.

## Развёртывания моделей, квоты и стоимость \{#deployments-quotas-cost}

**Тип развёртывания (deployment type)** — вариант запуска модели, который определяет границы обработки запросов, способ выделения мощности и механизм оплаты.

**Квота (quota)** — объём, который доступен подписке для модели или категории развёртываний в заданной области действия. Квота разрешает выделить этот объём; вычислительная мощность при этом не покупается.

**TPM (tokens per minute, токены в минуту)** — лимит частоты по объёму токенов. Оценка, по которой Azure OpenAI ограничивает запросы, отличается от количества токенов для выставления счёта.

**RPM (requests per minute, запросы в минуту)** — лимит частоты запросов. Проверка на интервалах короче минуты может приводить к отказам при всплесках нагрузки.

**HTTP 429 (Too Many Requests)** — ответ, которым сервис модели отклоняет запрос при превышении лимита частоты.

**Экспоненциальная отсрочка (exponential backoff)** — политика повторов, при которой после последовательных неудачных попыток задержка увеличивается. Случайный разброс задержки (jitter) распределяет повторы разных клиентов во времени.

**PTU (provisioned throughput unit)** — единица зарезервированной вычислительной мощности для модели. Фактическая пропускная способность зависит от модели и рабочей нагрузки.

**Azure Reservation** — финансовое обязательство, которое даёт скидку на использование зарезервированной пропускной способности, если оно подпадает под условия обязательства. Управляется отдельно от развёртывания, которое потребляет мощность.

**Пакетное развёртывание (batch deployment)** — развёртывание модели, которое асинхронно обрабатывает группы запросов с пакетными тарифами на токены и квотой на токены в очереди. Оно не используется для интерактивных запросов.
