# Глоссарий

Здесь собраны определения всех терминов, которые вводятся в уроках. Строка **Новые термины** в конце каждого урока ведёт к его группе. Глоссарий пополняется вместе с курсом.

Проверено на 17.10.2026. Источники каждой группы приведены в разделе «Источники» соответствующего урока.

## Как устроен Azure \{#how-azure-is-organised}

**Тенант (tenant)** — экземпляр Microsoft Entra ID, в котором хранятся удостоверения организации и объекты каталога.

**Группа управления (management group)** — область действия общих правил Azure, объединяющая подписки или другие группы управления. Назначения прав доступа и политик могут распространяться вниз по этой иерархии.

**Подписка (subscription)** — область администрирования ресурсов Azure, в которой накапливаются начисления за потребление сервисов в рамках соответствующих условий оплаты.

**Группа ресурсов (resource group)** — контейнер для ресурсов Azure с общим жизненным циклом, включая их последующее удаление.

**Ресурс (resource)** — объект, которым управляет Azure: например, среда для запуска приложения, учётная запись хранения или база данных.

**Поставщик ресурсов (resource provider)** — служба Azure, которая предоставляет типы ресурсов и обрабатывает операции с их экземплярами.

**Область действия (scope)** — набор ресурсов Azure, на который распространяется назначение настройки управления, например роли или политики.

**Идентификатор ресурса (resource ID)** — полный идентификатор ресурса Azure. Он включает области действия и путь к поставщику, которые определяют место ресурса в иерархии управления.

**Azure Resource Manager (ARM)** — общий слой развёртывания и управления в Azure, который принимает запросы управления и направляет их поставщикам ресурсов.

**Плоскость управления (control plane)** — операции создания, настройки и удаления ресурсов.

**Плоскость данных (data plane)** — операции использования сервиса, который предоставляет ресурс: например, чтение BLOB-объектов или запрос к индексу.

**Регион (region)** — географическая область с центрами обработки данных Azure и обслуживающей инфраструктурой, в которой можно развёртывать региональные сервисы.

**Зона доступности (availability zone)** — отдельная группа центров обработки данных внутри региона Azure. Зона независима от других по электропитанию, охлаждению и сети.

**Зональный ресурс (zonal resource)** — ресурс, развёрнутый в выбранной зоне доступности.

**Ресурс с избыточностью между зонами (zone-redundant resource)** — ресурс, который сервис реплицирует или распределяет по нескольким зонам.

**Тег (tag)** — метаданные в виде пары «имя — значение», назначаемые ресурсу Azure, группе ресурсов или подписке для организации ресурсов и учёта расходов. Ресурсы не наследуют теги группы автоматически.

**Бюджет (budget)** — целевое значение расходов или потребления для заданной области действия и периода. При достижении настроенных порогов отправляются уведомления; потребление не останавливается.

## Удостоверения I — Microsoft Entra ID \{#entra-id}

**Microsoft Entra ID** — сервис Microsoft для управления удостоверениями и доступом людей и рабочих нагрузок.

**Пользователь (user)** — удостоверение в каталоге, которое представляет человека. Пользователь может входить в систему и получать права доступа.

**Группа безопасности (security group)** — группа в каталоге, через членство в которой предоставляют доступ к ресурсам. Это сокращает число индивидуальных назначений прав.

**Регистрация приложения (app registration)** — конфигурация удостоверения приложения в его домашнем тенанте: идентификатор клиента, настройки входа и разрешения API, которые приложение предоставляет клиентам. Объект приложения служит шаблоном для локальных субъектов-служб в тенантах.

**Субъект-служба (service principal)** — локальное удостоверение рабочей нагрузки в тенанте Microsoft Entra. Ему можно выдать права доступа. Для регистраций приложений и управляемых удостоверений используются разные типы субъектов-служб.

**Управляемое удостоверение (managed identity)** — удостоверение рабочей нагрузки, учётными данными которого управляет Azure. Рабочие нагрузки с поддержкой этого механизма могут получать токены доступа Microsoft Entra, не работая с учётными данными напрямую.

**Управляемое удостоверение, назначаемое системой (system-assigned managed identity)** — управляемое удостоверение, жизненный цикл которого связан с одним ресурсом Azure. Удаление ресурса приводит к удалению удостоверения.

**Управляемое удостоверение, назначаемое пользователем (user-assigned managed identity)** — управляемое удостоверение, созданное как отдельный ресурс Azure. Оно существует независимо от рабочих нагрузок, к которым подключено.

**Идентификатор клиента (client ID)** — идентификатор приложения или управляемого удостоверения, по которому его выбирают при настройке аутентификации. Знание идентификатора не доказывает, что вызывающая сторона действует от имени этого удостоверения.

**Идентификатор субъекта (principal ID)** — идентификатор объекта субъекта-службы, который представляет рабочую нагрузку в тенанте. Используется при выдаче прав этому субъекту.

**Идентификатор ресурса Azure (Azure resource ID)** — полный путь Azure Resource Manager, который однозначно указывает на любой ресурс Azure. Например, поле `id` удостоверения, назначаемого пользователем, содержит подписку, группу ресурсов, поставщика, тип и имя ресурса.

**Токен доступа (access token)** — учётные данные, которые предъявляют защищённому API для проверки доступа. Токен выдаётся для конкретной аудитории и действует ограниченное время. Он не связан с текстовыми токенами, которые считает языковая модель.

**Аудитория (audience)** — API, которому предназначен токен. В токене доступа JWT она указана в утверждении `aud`.

**Токен идентификации (ID token)** — токен OpenID Connect, который сообщает клиенту об аутентификации пользователя. Он не предназначен для вызова другого API.

**Аутентификация (authentication)** — установление того, кто обращается к сервису.

**Авторизация (authorisation)** — решение о том, разрешено ли вызывающей стороне выполнить конкретную операцию с ресурсом.

## RBAC и доступ без ключей \{#rbac-and-keyless-access}

**Azure RBAC (управление доступом на основе ролей, role-based access control)** — система авторизации Azure, которая предоставляет субъекту безопасности права на операции в заданной области действия. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/role-based-access-control/overview)

**Определение роли (role definition)** — набор разрешённых операций управления или работы с данными, права на которые можно предоставить субъекту безопасности.

**Назначение роли (role assignment)** — связь между субъектом безопасности, определением роли и областью действия.

**Наследование прав (inheritance)** — распространение назначения роли с родительской области действия на вложенные ресурсы. Более узкое назначение не отменяет унаследованные разрешения.

**DefaultAzureCredential** — класс учётных данных из Azure Identity, который перебирает заранее настроенную цепочку источников токена, включая учётные данные разработчика и рабочей нагрузки в среде выполнения. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/dotnet/azure/sdk/authentication/credential-chains)

**Детерминированные учётные данные (deterministic credential)** — явно выбранные учётные данные с предсказуемым источником аутентификации. Пример — `ManagedIdentityCredential` для рабочей нагрузки, работающей в Azure.

**Федерация удостоверений рабочей нагрузки (workload identity federation)** — доверие, которое позволяет рабочей нагрузке обменивать токен внешнего поставщика удостоверений на токен доступа Entra без хранения секрета клиента.

**Учётные данные федеративного удостоверения (federated identity credential)** — настройки доверия в Entra, которые задают допустимые значения издателя, субъекта токена и аудитории. Сами по себе они не предоставляют права на ресурсы Azure. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/entra/workload-id/workload-identity-federation-create-trust-user-assigned-managed-identity)

**OIDC (OpenID Connect)** — протокол удостоверения личности, по которому издатель выдаёт токен удостоверения. При федерации между GitHub и Azure этот токен идентифицирует задание и обменивается на токен доступа Entra.

## Сети для разработчика приложений \{#networking}

**Azure Virtual Network (VNet, виртуальная сеть)** — изолированное частное адресное пространство в пределах одного региона и одной подписки, где ресурсы могут взаимодействовать по частной сети. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/concepts-and-best-practices)

**Подсеть (subnet)** — часть адресного пространства VNet, выделенная для ресурсов или интеграции с сервисом. К подсети можно применять средства сетевого контроля.

**Группа безопасности сети (NSG)** — набор правил для входящих и исходящих пакетов с учётом состояния соединений. Правила разрешают или запрещают трафик по адресам, портам и протоколу. Группу привязывают к подсети или сетевому интерфейсу. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/network-security-groups-overview)

**Частная конечная точка (private endpoint)** — сетевой интерфейс с частным IP-адресом в VNet, который обеспечивает подключение к поддерживаемому сервису через Azure Private Link. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/private-link/private-endpoint-overview)

**Конечная точка службы (service endpoint)** — настройка подсети, которая передаёт поддерживаемому сервису Azure удостоверение VNet через магистральную сеть Azure. Адрес назначения при этом остаётся публичным адресом сервиса. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/virtual-network-service-endpoints-overview)

**Частная зона DNS (private DNS zone)** — пространство имён DNS, записи которого доступны через связанные VNet и правильно настроенную пересылку запросов DNS. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/dns/private-dns-virtual-network-links)

**Интеграция с VNet (VNet integration)** — механизм подключения управляемого приложения к VNet. Возможности входящих и исходящих соединений зависят от сервиса размещения. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/app-service/overview-vnet-integration)

**Входящий трафик (ingress)** — трафик, который пересекает рассматриваемую границу приложения или сети по направлению внутрь.

**Исходящий трафик (egress)** — трафик, который пересекает рассматриваемую границу приложения или сети по направлению наружу.

**Топология hub-and-spoke (центральная сеть и периферийные сети)** — топология, в которой VNet рабочих нагрузок подключены к общей центральной VNet ради общих сетевых функций, например DNS, маршрутизации и проверки трафика.

**Пиринг VNet (VNet peering)** — соединение виртуальных сетей для обмена трафиком по частной сети. Пиринг нетранзитивен. ↗ [Microsoft Learn](https://learn.microsoft.com/ru-ru/azure/virtual-network/virtual-networks-faq)

**Брандмауэр веб-приложений (web application firewall, WAF)** — средство проверки запросов HTTP(S) по правилам веб-безопасности для обнаружения или блокировки атак.

## Выбор вычислительной среды \{#compute}

**План App Service (App Service plan)** — вычислительные ресурсы и тарифный уровень, на которых работают одно или несколько приложений App Service.

**Среда Container Apps (Container Apps environment)** — управляемая граница, внутри которой объединены контейнерные приложения и задания с общими настройками сети и журналирования.

**Профиль рабочей нагрузки (workload profile)** — конфигурация Container Apps, которая определяет вычислительные ресурсы и память, доступные назначенным этому профилю приложениям.

**Реплика (replica)** — работающий экземпляр ревизии Container Apps. При масштабировании приложения реплики добавляются или удаляются.

**Ревизия (revision)** — неизменяемый снимок образа контейнера приложения и настроек масштабирования.

**Масштабирование до нуля (scale to zero)** — уменьшение числа работающих экземпляров до нуля при отсутствии запросов или задач. Внешний триггер позволяет снова запустить экземпляры, когда появятся новые запросы или задачи.

**Холодный старт (cold start)** — подготовка нового экземпляра приложения к обработке запросов и связанная с ней задержка, включая выделение ресурсов и инициализацию приложения.

**Правило масштабирования (scale rule)** — декларативное соответствие между сигналом спроса на ресурсы, например HTTP-трафиком или числом ожидающих сообщений в очереди, и нужным числом работающих экземпляров.

**Постоянно готовый экземпляр (always-ready instance)** — ресурсы, которые намеренно оставляют запущенными, чтобы сократить задержку при старте. Их оплата зависит от сервиса размещения и плана.

**Пул узлов (node pool)** — группа рабочих узлов Kubernetes с общей конфигурацией, которой кластер управляет как единым целым.

## Хранение данных \{#data}

**Паттерн доступа (access pattern)** — необходимые для рабочей нагрузки операции чтения и записи: по каким ключам находить данные, какие запросы выполнять, как часто обновлять записи и насколько свежими должны быть результаты.

**Объектное хранилище (object storage)** — хранилище именованных объектов: каждый содержит байты и метаданные. Azure Blob Storage использует эту модель для документов и другого неструктурированного содержимого.

**Контейнер блобов (blob container)** — именованная группа блобов в учётной записи хранения Azure. Контейнер также может ограничивать область действия роли, которая предоставляет доступ к данным.

**Основное хранилище (system of record)** — хранилище, где находится основная копия конкретных данных. Производные копии можно восстановить из него или сверить с ним.

**pgvector** — расширение PostgreSQL для хранения векторов и поиска по ним; идентификатор расширения — `vector`.

**Ключ раздела (partition key)** — свойство элемента, по значению которого Azure Cosmos DB определяет логический раздел. От него зависит распределение связанных данных и нагрузки от запросов.

**Единица запроса (request unit, RU)** — нормализованная мера расхода ресурсов на операцию базы данных в Azure Cosmos DB, учитывающая CPU, ввод-вывод и память. Выделенная пропускная способность выражается в `RU/s`.

**Уровень согласованности (consistency level)** — требования к свежести данных и порядку, в котором чтение базы видит результаты записи.

**Cache-aside (кэширование по запросу)** — паттерн, при котором приложение сначала читает кэш. При промахе оно загружает данные из основного хранилища и помещает результат в кэш.

**Срок жизни (TTL)** — срок, по истечении которого сохранённая запись становится просроченной. Он ограничивает время, в течение которого запись можно использовать повторно.

**Инвалидация кэша (cache invalidation)** — удаление или замена кэшированных данных, когда изменение исходных данных делает их непригодными для повторного использования.

**Роль плоскости данных (data-plane role)** — роль Azure, которая предоставляет право выполнять операции [плоскости данных](#how-azure-is-organised). Например, `Storage Blob Data Reader` разрешает читать блобы и получать их список.

## Правила использования платформы и архитектурные рекомендации \{#governance-and-frameworks}

**Azure Policy** — сервис Azure, который проверяет ресурсы по правилам конфигурации и применяет заданные в них эффекты.

**Определение политики (policy definition)** — повторно используемое правило, содержащее условия, эффект и параметры, необходимые для проверки ресурса.

**Эффект политики (policy effect)** — действие при выполнении условия политики: например, аудит, отклонение запроса, изменение поддерживаемых свойств или развёртывание связанного ресурса.

**Назначение политики (policy assignment)** — связь определения политики или инициативы с областью действия, включающая значения параметров и настройки применения эффектов.

**Инициатива политик (policy initiative)** — группа определений для общей цели, которыми управляют и которые назначают вместе. Другое название — набор политик (policy set).

**Состояние соответствия (compliance state)** — результат проверки ресурса по назначенной политике, которая к нему применима.

**Cloud Adoption Framework (CAF)** — рекомендации Microsoft по планированию, подготовке, освоению и эксплуатации облачных сред, включая общие правила их использования, контроль соблюдения этих правил и распределение ответственности в организации.

**Целевая зона (landing zone)** — среда Azure с общими правилами, в которой предусмотрены организация ресурсов, доступ, сети и порядок эксплуатации, необходимые для размещения рабочих нагрузок.

**Well-Architected Framework** — рекомендации по проектированию и архитектурному ревью рабочих нагрузок Azure. Охватывают пять направлений: надёжность (Reliability), безопасность (Security), оптимизация затрат (Cost Optimization), операционная эффективность (Operational Excellence) и эффективность производительности (Performance Efficiency).

**Cost Management** — возможности Microsoft для анализа, мониторинга и оптимизации облачных расходов.

**Microsoft Defender for Cloud** — сервис Microsoft для проверки состояния безопасности и защиты рабочих нагрузок. Набор доступных возможностей зависит от включённых планов.

**Управление состоянием безопасности облака (cloud security posture management, CSPM)** — проверка конфигурации облачных ресурсов, которая выявляет недостатки безопасности и помогает выбрать меры по их устранению.
