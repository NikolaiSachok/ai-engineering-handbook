# Часть II — Современный .NET

Вызов модели — лишь часть приложения. Ему ещё нужны HTTP API, настройки, работа с данными, тесты и обработка долгих запросов. Эта часть собирает необходимые для этого возможности современного .NET.

Сначала разберёшь платформу и устройство ASP.NET Core, затем общие механизмы приложения и асинхронную работу с потоками данных. Доступ к данным и тестирование подготовят код к сборке в контейнер, а последний урок свяжет эту основу с AI-библиотеками.

*Где это на [карте курса](../intro.md#course-map): код приложения — от HTTP-запроса до вызова модели.*

## Что внутри \{#whats-inside}

{/* slugs: dotnet-platform, aspnet-core, extensions-backbone, async-streaming-cancellation, data-access, testing, containers-and-aspire, ai-in-dotnet */}

- **[Платформа .NET сегодня](./dotnet-platform.md)** — среда выполнения, SDK, цикл поддержки, файлы проектов, `dotnet` CLI и NuGet. Сопоставишь .NET Framework и современный .NET и учтёшь цикл поддержки при выборе платформы и поддерживаемой версии для проекта.
- **[ASP.NET Core](./aspnet-core.md)** — запуск приложения, конвейер middleware, маршрутизация, minimal APIs и контроллеры. Разберёшь и единый формат описания ошибок — problem details.
- **Основа приложения — Microsoft.Extensions** 🚧 — внедрение зависимостей и время жизни объектов, поставщики конфигурации, паттерн Options (options pattern) и журналирование. Свяжешь эти механизмы в одном приложении.
- **Асинхронность, потоки данных и отмена** 🚧 — `Task`, `IAsyncEnumerable`, server-sent events, тайм-ауты и отмена операций. Основная задача — долгие вызовы LLM и постепенная передача ответа клиенту.
- **[Доступ к данным](./data-access.md)** — миграции, отслеживание изменений и типичные проблемы производительности в EF Core. Разберёшь, когда удобнее использовать Dapper или SQL напрямую.
- **Тестирование** 🚧 — xUnit, интеграционные тесты с `WebApplicationFactory` и Testcontainers. Отдельный вопрос — как проверять код, который зависит от ответов LLM.
- **Контейнеры и Aspire** 🚧 — сборка образа через `dotnet publish`, Aspire app host, локальный запуск связанных сервисов и их телеметрия.
- **AI в .NET** 🚧 — `Microsoft.Extensions.AI`, SDK Azure OpenAI и OpenAI, абстракции для векторных данных и Microsoft Agent Framework для .NET. Разберёшь, какую задачу решает каждый из этих инструментов.

## Что нужно знать заранее \{#prerequisites}

Часть I не обязательна: устройство .NET-приложения можно изучать локально, отдельно от Azure. Понадобится опыт работы с C# или другим типизированным языком; знание современного .NET заранее не требуется.

## Что изменится после этой части \{#what-changes-after-this-part}

Ты сможешь собрать ASP.NET Core-приложение с конфигурацией, зависимостями, доступом к данным и тестами, упаковать его в контейнер и посмотреть локальную телеметрию через Aspire. Будешь понимать, как организовать долгий вызов модели, передавать ответ по мере генерации и отменять работу, когда запрос больше не нужен.
