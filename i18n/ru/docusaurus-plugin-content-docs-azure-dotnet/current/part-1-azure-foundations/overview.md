# Часть I — Основы Azure

Прежде чем запускать приложение в Azure, нужно понять, где будут жить его ресурсы, кто получит к ним доступ и как ты заметишь сбой. Эта часть даёт основу для таких решений: от устройства платформы и идентификации до сетей, вычислений и эксплуатации.

Уроки идут в порядке, в котором удобно разбирать архитектуру приложения. Сначала — границы ресурсов и доступа, затем — выбор сервисов, а после — воспроизводимое создание инфраструктуры, наблюдаемость и общие правила её использования.

*Где это на [карте курса](../intro.md#course-map): основание для приложения — ресурсы, доступ, сеть и эксплуатация.*

## Что внутри \{#whats-inside}

{/* slugs: how-azure-is-organised, entra-id, rbac-and-keyless-access, networking, compute, data, messaging, secrets-and-configuration, infrastructure-as-code, observability, governance-and-frameworks */}

- **Как устроен Azure** 🚧 — тенант, группы управления, подписки, группы ресурсов и ресурсы; Azure Resource Manager, регионы и зоны. Разберёшь, как эта иерархия связана с правилами использования платформы и учётом расходов.
- **Идентификация I — Microsoft Entra ID** 🚧 — пользователи и группы, регистрации приложений, субъекты-службы и управляемые удостоверения. Проследишь, какой токен приложение предъявляет сервису и откуда он берётся.
- **Идентификация II — RBAC и доступ без ключей** 🚧 — роли, области действия и наследование прав, различие между доступом к управлению ресурсом и доступом к его данным. Здесь же — `DefaultAzureCredential` и федерация удостоверений для CI без хранения секретов.
- **Сети для разработчика приложений** 🚧 — виртуальные сети, подсети, группы безопасности сети, частные конечные точки и service endpoints, частный DNS и интеграция PaaS с сетью. Сравнишь Front Door, Application Gateway и Load Balancer для входящего трафика и разберёшь схему hub-and-spoke.
- **Выбор вычислительной среды** 🚧 — App Service, Container Apps, Functions, AKS или виртуальная машина. Выбирать будешь по характеру нагрузки, способу масштабирования и затратам на эксплуатацию.
- **Хранение данных** 🚧 — Blob Storage, Azure SQL, PostgreSQL с pgvector, Cosmos DB и Azure Managed Redis. Сопоставишь их с тем, как приложение читает и записывает данные, включая согласованность и векторный поиск.
- **Сообщения и события** 🚧 — команды, события и потоки данных на примере Service Bus, Event Grid и Event Hubs. Отдельно разберёшь повторные попытки, порядок обработки и сообщения, которые не удалось обработать.
- **Секреты и конфигурация** 🚧 — секреты, ключи и сертификаты в Key Vault, настройки в App Configuration и доступ через управляемое удостоверение. В план урока входят права доступа и ротация секретов.
- **Инфраструктура как код** 🚧 — ARM, Bicep, Terraform и Azure Developer CLI (`azd`). Разберёшь модули, предварительный просмотр изменений и расхождения между описанной и фактической инфраструктурой.
- **Наблюдаемость** 🚧 — Azure Monitor, Log Analytics, Application Insights и OpenTelemetry. Запросы KQL помогут связать телеметрию с вопросами о работе приложения.
- **Правила использования платформы и архитектурные рекомендации** 🚧 — Azure Policy, целевые зоны Cloud Adoption Framework и Well-Architected Framework. Здесь же — теги, бюджеты, управление расходами и Defender for Cloud.
