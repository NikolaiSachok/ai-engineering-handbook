# Часть I — Основы Azure

Прежде чем запускать приложение в Azure, нужно понять, где будут жить его ресурсы, кто получит к ним доступ и как ты заметишь сбой. Эта часть даёт основу для таких решений: от устройства платформы и удостоверений до сетей, вычислений и эксплуатации.

Уроки идут в порядке, в котором удобно разбирать архитектуру приложения. Сначала — границы ресурсов и доступа, затем — выбор сервисов, а после — воспроизводимое создание инфраструктуры, наблюдаемость и общие правила её использования.

*Где это на [карте курса](../intro.md#course-map): основание для приложения — ресурсы, доступ, сеть и эксплуатация.*

## Что внутри \{#whats-inside}

{/* slugs: how-azure-is-organised, entra-id, rbac-and-keyless-access, networking, compute, data, messaging, secrets-and-configuration, infrastructure-as-code, observability, governance-and-frameworks */}

- **[Как устроен Azure](./how-azure-is-organised.md)** — тенант, группы управления, подписки, группы ресурсов и ресурсы; Azure Resource Manager, регионы и зоны. Разберёшь, как эта иерархия связана с правилами использования платформы и учётом расходов.
- **[Удостоверения I — Microsoft Entra ID](./entra-id.md)** — пользователи и группы, регистрации приложений, субъекты-службы и управляемые удостоверения, назначаемые системой или пользователем. Проследишь, какой токен приложение предъявляет сервису и откуда он берётся.
- **Удостоверения II — RBAC и доступ без ключей** 🚧 — роли, области действия и наследование прав, различие между доступом к управлению ресурсом и доступом к его данным. Здесь же — `DefaultAzureCredential` и федерация удостоверений для CI без хранения секретов.
- **Сети для разработчика приложений** 🚧 — виртуальные сети, подсети, группы безопасности сети, частные конечные точки и конечные точки службы (service endpoints), частный DNS и интеграция PaaS с сетью. Сравнишь Front Door, Application Gateway и Load Balancer для входящего трафика и разберёшь схему hub-and-spoke.
- **Выбор вычислительной среды** 🚧 — App Service, Container Apps, Functions (Flex Consumption), AKS или виртуальная машина. Выбирать будешь по характеру рабочей нагрузки, способу масштабирования и затратам на эксплуатацию.
- **Хранение данных** 🚧 — Blob Storage, Azure SQL, гибкий сервер PostgreSQL с pgvector, Cosmos DB и Azure Managed Redis. Сопоставишь их с тем, как приложение читает и записывает данные, включая единицы запросов Cosmos DB (RU), согласованность и векторный поиск.
- **Сообщения и события** 🚧 — команды, события и потоки данных на примере Service Bus, Event Grid и Event Hubs. Отдельно разберёшь повторные попытки, порядок обработки и сообщения, которые не удалось обработать.
- **Секреты и конфигурация** 🚧 — секреты, ключи и сертификаты в Key Vault, настройки в App Configuration и доступ через управляемое удостоверение. В план урока входят права доступа и ротация секретов.
- **Инфраструктура как код** 🚧 — ARM, Bicep, Terraform и Azure Developer CLI (`azd`). Разберёшь модули, предварительный просмотр изменений и расхождения между описанной и фактической инфраструктурой.
- **Наблюдаемость** 🚧 — Azure Monitor, Log Analytics, Application Insights и OpenTelemetry. Запросы KQL помогут связать телеметрию с вопросами о работе приложения.
- **[Правила использования платформы и архитектурные рекомендации](./governance-and-frameworks.md)** — Azure Policy, целевые зоны Cloud Adoption Framework и Well-Architected Framework. Здесь же — теги, бюджеты, управление расходами и Defender for Cloud.

## Что нужно знать заранее \{#prerequisites}

Ничего из курса знать не нужно — он начинается здесь. Предполагается опыт разработки и эксплуатации систем; знание Azure или другой облачной платформы заранее не требуется.

## Что изменится после этой части \{#what-changes-after-this-part}

Ты сможешь объяснить иерархию ресурсов и области действия прав, сопоставить варианты сетей, вычислений, хранения данных и обмена сообщениями для конкретной рабочей нагрузки. Будешь различать задачи инфраструктуры как кода, телеметрии и общих правил использования платформы, прежде чем применять их в следующих частях.
