# Часть III — Запуск LLM в Azure

Чтобы приложение работало с LLM в Azure, недостаточно выбрать модель. Нужно организовать доступ, выбрать развёртывание, учитывать квоты и расходы, подключить данные и проверять качество ответов. Эта часть связывает эти задачи с сервисами платформы.

Начнёшь с Microsoft Foundry и развёртываний моделей. Затем перейдёшь к защите, поиску по документам и агентам, а после — к оценке качества, AI-шлюзу и требованиям корпоративной среды. В конце сопоставишь разработку кодом с возможностями Copilot Studio и Power Platform.

*Где это на [карте курса](../intro.md#course-map): модель и её окружение — данные, агенты, проверки и доступ.*

## Что внутри \{#whats-inside}

{/* slugs: microsoft-foundry, deployments-quotas-cost, platform-safety, rag-on-ai-search, document-ingestion, agents-on-azure, evaluation-and-tracing, ai-gateway, enterprise-ai, copilot-studio-power-platform */}

- **[Microsoft Foundry](./microsoft-foundry.md)** — ресурсы и проекты, каталог моделей, место Azure OpenAI и модели других поставщиков. Разберёшь, как организовать работу с моделями на платформе.
- **[Развёртывания моделей, квоты и стоимость](./deployments-quotas-cost.md)** — типы развёртываний Standard, Global, Data Zone и Provisioned, квоты TPM/RPM, ограничения частоты запросов и размещение данных. Сопоставишь их с моделью расходов приложения.
- **[Защита на уровне платформы](./platform-safety.md)** — фильтры содержимого, Prompt Shields и groundedness detection (проверка опоры ответа на источники). Разберёшь и границы этой защиты: какие риски остаются на стороне приложения и требуют ограничителей из курса [RAG & Agents](/rag-agents/).
- **[RAG на Azure AI Search](./rag-on-ai-search.md)** — индексы, гибридный поиск, semantic ranker, встроенная векторизация и agentic retrieval. Сравнишь этот путь с векторным поиском в PostgreSQL через pgvector и в Cosmos DB.
- **[Приём документов](./document-ingestion.md)** — Content Understanding и Document Intelligence: распознавание текста, структура страниц, извлечение полей и Markdown для RAG.
- **[Агенты в Azure](./agents-on-azure.md)** — Foundry Agent Service и самостоятельное размещение Microsoft Agent Framework. Разберёшь инструменты, MCP, память, взаимодействие нескольких агентов и одобрение действий человеком.
- **[Оценка качества и трассировка](./evaluation-and-tracing.md)** — проверки и трассировка в Foundry, связанные с подходами к оценке качества из курса [RAG & Agents](/rag-agents/). Сопоставишь проверки на заранее подготовленных примерах с проверками во время эксплуатации.
- **[AI-шлюз](./ai-gateway.md)** — API Management перед развёртываниями моделей: лимиты токенов, распределение нагрузки, переключение при сбоях, семантическое кэширование и журналирование использования.
- **[AI для корпоративной среды](./enterprise-ai.md)** — частные сети для доступа к моделям, доступ без ключей, размещение данных и целевая зона для AI-нагрузок.
- **[Copilot Studio и Power Platform](./copilot-studio-power-platform.md)** — Power Apps, Power Automate, Dataverse и Copilot Studio. Разберёшь, где инструменты low-code соединяются с API, написанным вручную, и по каким причинам команда выбирает один из подходов.

## Что нужно знать заранее \{#prerequisites}

Нужны уроки части I об удостоверениях и доступе, устройстве ресурсов, вычислениях и инфраструктуре как коде: нужно понимать, кто вызывает сервис и как создаются его ресурсы. За основами поиска, агентов и оценки качества обращайся к [RAG & Agents](/rag-agents/). Для примеров на .NET пригодятся соответствующие уроки части II.

## Что изменится после этой части \{#what-changes-after-this-part}

Ты сможешь сопоставить развёртывания моделей, квоты и расходы; поиск через AI Search, pgvector и Cosmos DB; управляемое и самостоятельное размещение агентов. Будешь понимать границы защиты платформы и выбирать проверки качества, трассировку и средства AI-шлюза с учётом частного доступа и размещения данных.
