# Часть IV — Поставка ПО с помощью AI в стеке Microsoft

Приложение с моделью нужно регулярно менять и выпускать. Эта часть связывает код, инфраструктуру Azure и работу агента для программирования в один процесс поставки ПО.

Сначала разберёшь автоматическую сборку и развёртывание с доступом без постоянных секретов. Затем — работу агентов с .NET-проектом и проверки их изменений. Последний урок посвящён выкатке: как направлять трафик на новую версию и возвращаться к прежней при проблемах.

*Где это на [карте курса](../intro.md#course-map): от изменения к работающей версии — CI, агенты и выкатка.*

## Что внутри \{#whats-inside}

{/* slugs: pipelines-to-azure, coding-agents-dotnet, releasing-safely */}

- **Конвейеры поставки в Azure** 🚧 — GitHub Actions и Azure DevOps Pipelines, федерация OIDC, окружения и одобрения. Разберёшь и применение `azd` в CI.
- **Агенты для программирования в .NET-проекте** 🚧 — GitHub Copilot и другие агенты: агентный режим, coding agent и инструкции проекта. Их работу свяжешь с циклом и проверками из курса [AI SDLC](/ai-sdlc/).
- **Безопасный выпуск изменений** 🚧 — слоты App Service и ревизии Container Apps, распределение трафика и откат. В план входят также расхождения инфраструктуры с её описанием и проверки цепочки поставки ПО.

## Что нужно знать заранее \{#prerequisites}

Эта часть опирается на части I–III: инфраструктуру и доступ в Azure, устройство .NET-приложения и работу с моделями. Возвращайся к нужным урокам, когда разбираешь соответствующий шаг поставки.

## Что изменится после этой части \{#what-changes-after-this-part}

Ты сможешь описать процесс от изменения в .NET-проекте до выкатки в Azure: как CI получает доступ, где проверяются изменения агента и что происходит при неудачном выпуске. Сможешь выбрать подход к распределению трафика и откату для среды своего приложения.
